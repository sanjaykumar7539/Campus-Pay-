# ADR-0004: Institution Ledger as the Authoritative Financial Record

**ADR ID:** ADR-0004  
**Title:** Institution Ledger module; Wallet as a representation of ledger position  
**Status:** Proposed (pending approval)  
**Date:** 21 September 2026  
**Decision Makers:** CampusPay Engineering Team

---

# Context

Campus Operating Model v0.2 (§3, §4.4, §9) establishes that the **Institution Ledger is authoritative**, that a **Wallet is only the customer's spendable-value representation**, and that historical financial events are never rewritten. The MVP treated `wallets.balance_minor` as truth and `wallet_transactions` as a side record. ADR-0003 (Rule 1/5) forbids new module folders and dependency changes without an ADR.

# Decision

1. Add module `backend/modules/ledger/` owning `LedgerEntry` (append-only Financial Events: RECHARGE, PURCHASE implemented; ADJUSTMENT, REFUND, SETTLEMENT, WALLET_STATUS_CHANGE recognised but rejected because their policies are OPEN).
2. A customer's Financial Position is the `position_after_cu` of their latest entry (per-customer sequence, unique per customer).
3. Wallet (`available_cu`) is set only by the Wallet module, only after the ledger entry exists, and must equal the ledger position. Enforced by an ORM guard **and** a database trigger; ledger and audit tables reject UPDATE/DELETE by ORM guard **and** trigger.
4. `wallet_transactions` remains as a non-authoritative wallet-side movement record referencing `ledger_entry_id`.
5. Ledger/wallet discrepancy response is MG-16 (OPEN): the system detects (`/reports/reconciliation`) and fails closed; it does not repair.
6. Dependencies: Wallet → Ledger; Ledger → (none). Demo funding is a ledger `RECHARGE` with `origin=DEMO`; production recharge (MG-03) is not implemented.

# Consequences

Positive: single financial source of truth; tamper-evident history; wallet drift is detectable. Negative: one more module and an extra write per financial event. Reversal/refund/adjustment must be new events when their policies are approved.

# Relationship to Other ADRs

Extends ADR-0002/0003 (new module, dependency matrix). See ADR-0007 for units.
